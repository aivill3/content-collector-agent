Sep 28, 2026
0. 전체 분석 요약
와이어프레임 16개 화면(아트보드)과 공통 레이아웃 1개, 팝오버 1개를 18개 화면 단위로 정리했고, 기능 65개·Flow 14개·요구사항 40개로 연결했습니다. 확정되지 않은 정책·API·디자인 수치는 태그로 표시하고 13장 Decision Log에 모았습니다.
자료 범위. 분석 대상은 캔버스 "콘텐츠 수집 AI Agent 와이어프레임"의 아트보드 16개와, 같은 대화에서 결정된 사항(수집 로직 이식 코드 content-collector-agent, 설정 기본값, 기술 스택 제안)입니다. 대화 결정 사항은 출처를 "제공 문서"로, 와이어프레임에 그려진 내용은 "Wireframe"으로 구분합니다. 대화에서 제안만 되고 확정되지 않은 것(내부 API 경로, 테이블 구조)은 확정으로 쓰지 않았습니다.

주요 리스크.
게시판 수동 설정(SOURCE-004)은 대상 사이트 화면을 서비스 안에 띄우고 클릭 위치를 선택자로 바꾸는 기능이 필요합니다. 자바스크립트로 목록을 그리는 사이트는 별도 렌더링이 필요해 구현 난도가 가장 높습니다 [확인 필요].
네이버 검색 API는 일일 호출 한도가 있고 API HUB로 이전 중입니다(구 방식 2027-06-30 지원 종료, 제공 문서). 유저가 늘면 호출 한도가 병목이 됩니다. 관리자 화면에 "API 공유 호출"이 그려져 있으나 정책은 미정입니다 [정책 필요].
외부 판매 시 수집 기사 본문 제공의 저작권, robots.txt 준수, 관리자가 고객 키워드를 보는 범위에 대한 정책이 없습니다 [정책 필요].
인증(비밀번호 정책, 세션 만료, 회원가입 방식), 데이터 보존 기간, 요금제가 정의되지 않았습니다 [정책 필요].
확인이 필요한 사항(요약). 회원가입과 도입 문의의 흐름, 워크스페이스(여러 사용자가 한 조직을 공유) 개념 여부, 대시보드 "지금 수집" 버튼의 대상, 프리셋 "엄격·느슨" 값, 분석 최소 본문 길이 기본값, 관리자 메뉴의 멤버 노출 여부, 로그아웃·계정 설정 화면 부재. 전체 목록은 14장에 있습니다.

2. 사용자 Flow
서비스의 핵심은 한 방향 흐름이 아니라 되돌아오는 고리입니다. 수집 결과와 분석 결과가 다시 수집 소스(검색 키워드), 사전(불용어), 분석 설정으로 돌아가 다음 수집과 판정을 바꿉니다.

4. 화면설계서
18개 화면을 정의합니다. UI ID는 <화면 ID>-U<번호> 형식이며, 와이어프레임의 문구는 따옴표 안에 그대로 옮겼습니다. [N], [소스 이름] 같은 대괄호 값은 와이어프레임의 자리 표시이며 실제 데이터로 채워집니다. 모든 페이지 화면은 COMMON-001 레이아웃 안에 놓입니다(MEMBER-001 제외).

6. 기능 명세서
기능 65개 중 구현 판단이 필요한 핵심 기능 10개는 전체 양식으로, 나머지는 6-2 기능 카탈로그에 한 줄씩 정의했습니다. 각 기능의 Acceptance Criteria는 12장에 AC ID로 모았고 여기서는 ID로 연결합니다. 내부 API는 확정되지 않아 처리 규칙의 서버 요청은 모두 [API 확인 필요]입니다.
